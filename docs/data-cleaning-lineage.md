# 清理結果保存與分析來源綁定

`apply_cleaning` 現在先保存核准操作與原檔證據，再更新記憶體資料。
過去只修改記憶體，MCP 重啟後可能重新使用未清理原檔；本次修正讓重啟
重播同一批 typed cleaning 操作，逐步核對資料框，無法重現時停止載入。
原檔改變或清理收據損壞不能默默退回原始資料。

原始 bytes 以 SHA256 保存於專案的
`artifacts/phase_08_execute_exploration/data_lineage/sources/`。
每個資料集另有 append-only `cleaning.jsonl` 指向各次不可變的 JSON 收據。
收據保留原檔、格式、工作表、編碼、前一份收據、核准操作、執行紀錄及清理前後
完整資料框身分。資料框比對涵蓋值、列順序與 index、欄順序、dtype 及分類順序；
不接受重複或非字串欄名造成的身分混淆。不使用 pickle 或任意程式重播。

通用探索的完整數值紀錄新增 `input_evidence.source_binding`：使用同一
`PandasLoader` 解析保存的原檔，套用已保存的清理，再與實際分析輸入比較。
綁定包含 parser 正規化紀錄及全部輸入列的 source index；這些 index 指向
正規化後的原始資料列，不能冒稱是實體 CSV 行號。無可讀原檔的記憶體測試資料
明示 `unavailable`，不能宣稱已完成來源綁定。

歷史繪圖驗證只讀取當時固定的原檔快照與清理收據，核對 hashes 和前後鏈，
不重新解析、計算補值或擬合模型。後續清理不改寫先前的分析身分。
移除原始上傳檔仍可核對已保存的歷史證據；這不代表刪除上傳檔即可安全抹除
所有研究產物。更改欄名後不自動轉移已核准的角色或修改凍結計畫。
