# 清理結果保存與分析來源綁定

## 0.5.1：正式準備版本與採用

[`data_preparation`](DATA_PREPARATION.md) 已提供固定原始來源、清理與關聯規則、
研究族群、核准、release 及完整來源包。發布後的分析資料使用已核准 typed values，
不再次猜測缺值代碼、刪除全空欄或正規化 ID。`apply_cleaning` 不得直接修改這種資料；
需要建立子準備版本並重新核准。

Workbench 0.1.1 可比較／收起候選版本並按研究方向正式採用；後續新計畫使用該版本，
既有計畫、主要成果與 autoresearch 維持原本 dataVersion。準備本身保留不同人數、
分析單位數及逐值來源；各模型的 complete-case 納排仍是另外的分析紀錄。
以下說明保留早期版本的有效資料鎖定與一般單表清理行為，不應據此推論新版缺少準備契約。

## 2026-10-12：探索前固定有效資料版本

新增 `get_dataset_version(project_id, dataset_id)`，必須明選同專案資料集。
`rde-data-version-v1` 回傳原始來源／工作表／編碼、parser hash、資料框身份、
清理收據數與清理鏈 hash，以及整體 `version_sha256`。必要時保存原檔快照，
重播並核對每個清理轉換；不是臨床品質或清理策略核准。

原生 autoresearch 在建立佇列前固定所有專案資料的有效版本與選取順序，在恢复及
每次取得任務前核對。來源、資料框、資料集集合／順序或清理收據改變即阻擋。
即使新清理沒有改變數值，準備紀錄不同仍是不同版本。缺少新版基準的歷史佇列
不自動補認，須建立新研究輪次；舊結果保留。

這修正「每次實驗都有來源證據，但同一輪仍可能更換清理版本」的缺口；不等於
完整的清理候選分支、資料 release 採用、通用多表關聯與模型個案固定。
無原檔的內存測試／純想法佇列仍明示 unavailable，公開版本工具拒絕將其視為
verified。平台版本治理設計見 Workbench 的 `docs/DATA_PREPARATION_VERSIONS.md`。

## 既有的清理保存與歷史讀取

`apply_cleaning` 現在先保存核准操作與原檔證據，再更新記憶體資料。
過去只修改記憶體，MCP 重啟後可能重新使用未清理原檔；本次修正讓重啟
重播同一批 typed cleaning 操作，逐步核對資料框，無法重現時停止載入。
原檔改變或清理收據損壞不能默默退回原始資料。

原始 bytes 以 SHA256 保存於專案的
`artifacts/phase_08_execute_exploration/data_lineage/sources/`。
每個資料集另有 append-only `cleaning.jsonl` 指向各次不可變的 JSON 收據。
收據保留原檔、格式、工作表、編碼、前一份收據、核准操作、執行紀錄及清理前後
完整資料框身分。資料框比對涵蓋值、列順序與 index、欄順序、dtype 及分類順序；
不接受重複或非字串欄名造成的身分混淆。不使用 pickle 或任意程式重播。

通用探索的完整數值紀錄新增 `input_evidence.source_binding`：使用同一
`PandasLoader` 解析保存的原檔，套用已保存的清理，再與實際分析輸入比較。
綁定包含 parser 正規化紀錄及全部輸入列的 source index；這些 index 指向
正規化後的原始資料列，不能冒稱是實體 CSV 行號。無可讀原檔的記憶體測試資料
明示 `unavailable`，不能宣稱已完成來源綁定。

歷史繪圖驗證只讀取當時固定的原檔快照與清理收據，核對 hashes 和前後鏈，
不重新解析、計算補值或擬合模型。後續清理不改寫先前的分析身分。
移除原始上傳檔仍可核對已保存的歷史證據；這不代表刪除上傳檔即可安全抹除
所有研究產物。更改欄名後不自動轉移已核准的角色或修改凍結計畫。

## 驗收（2026-10-03，開發分支）

- 邊界測試涵蓋 CSV、XLSX 工作表、清理串接、列／欄／值／dtype 漂移、收據竄改、
  重複鏈、原檔變更、原子快照寫入失敗、歷史驗證不重載及完整重新載入。
- 完整 RDE 測試：**1,074 passed、5 optional skipped**；523.63 秒。
- 透過實際外部 MCP 執行公開 UCI 519 的 logistic、OLS、事件比例與傾向分數
  四種探索，每份均保存 299 列輸入的原檔綁定。此為指定規格的工程驗證。
- 另建立明確標示為 synthetic 的缺值測試資料：只移除 20 個
  `serum_creatinine` 值。只核准建議中的中位數補值，完全關閉並重啟 MCP，
  前後均為 299 列、一份清理收據、相同來源綁定與模型數值 SHA256。
  模型 SHA256：`1c90e60d5eef7d0927456372eb0e30e32c8d65a84403fcfbaddc3b3f2ed52ce9`。

本段未變更正式 runtime，沒有將 synthetic 結果當成臨床研究結論。
來源綁定是通用投稿圖的必要基礎；尚不代表通用探索已具備完整六格式圖表、
字典／期刊版次，或 LLM 評讀已全部通過語意驗收。
